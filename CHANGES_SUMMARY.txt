                    WINE/LINUX UI LAG FIX - CHANGES SUMMARY
================================================================================

ISSUE: UI lag to the degree of being unusable when running via Wine on Linux

INVESTIGATION RESULTS:
----------------------
The root cause was identified as an excessively fast timer (1ms interval) 
attempting to redraw visualization 1000 times per second. GDI+ operations 
(System.Drawing) are significantly slower under Wine than native Windows,
causing severe performance degradation.

CHANGES MADE:
-------------

1. PERFORMANCE FIX (MainWindowCore.cs)
   
   a) Timer Frequency Reduction:
      - Before: Timer visualEffectRefreshTimer = new(1)   // 1ms = 1000 fps
      - After:  Timer visualEffectRefreshTimer = new(16)  // 16ms = 60 fps
      - Impact: 94% reduction in redraw attempts
   
   b) Frame Skipping for DrawFFT():
      - Added isDrawingFFT flag to prevent concurrent FFT drawing
      - Wrapped drawing code in try-finally for safety
      - Prevents queue buildup of drawing operations
   
   c) Enhanced DrawWave() Safety:
      - Wrapped with try-finally to ensure isDrawing flag always resets
      - Prevents UI from freezing if drawing throws exception

2. CONFIGURABILITY (Majson.cs)
   
   - Added VisualEffectRefreshRate property to EditorSetting class
   - Default value: 16ms (~60 fps)
   - Applied in ReadEditorSetting() method
   - Users can adjust in EditorSetting.json for their system:
     * 16ms = 60 fps (default, balanced)
     * 33ms = 30 fps (better performance for slower systems)
     * 8ms = 120 fps (smoother for faster systems)
